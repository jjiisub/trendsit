# S1 질문과 결정

## Q1. GeekNews 수집 방식 → 결정(2026-10-07)
RSS와 상세 페이지를 쓰지 않는다. 평소는 메인(점수순) 1~2페이지, 지난 기간은 날짜별 목록 `past?day=`. 목록에서 제목, 원문 링크, 요약 앞부분, 점수, 댓글 수를 저장하고 본문은 원문 링크에서. topic id로 중복 제거. 원문 링크가 GeekNews 자신인 글은 빼고 건수만. 목록 요청은 몇 초 간격. 수집 리포트에 하루 신규 건수. 본문 성공률 90%는 원문 링크가 있는 글 기준이고, robots 차단·PDF·영상 등 의도적 건너뜀은 이유별로 세서 분모에서 빼며 403 같은 실패는 실패로 센다 → `reports/S1_report.md` 4장

## Q2. 트렌딩 기준 → 결정
"주간 페이지에 보이는 전부 수집, stars_this_week 누락 0, 0개면 실패". 언어별·월간 페이지는 추가하지 않는다

## Q3. repo_oneliner 관문 B → 결정
README 입력에서 마크다운·HTML 기호를 걷어 낸 본문을 모델에 주고, basis 검사는 정리된 본문 + description 기준. 관문 B 1회 재측정(기존 3회 상한과 별도). 라벨 파일은 PR 리뷰 때 사용자가 채운다

## Q4. S1 예산 → 결정(2026-10-08)
`specs.S1`을 0.06으로 올려 Q3 재측정을 끝까지 돌린다

## Q5. GeekNews "어제"의 경계 → 결정(2026-10-08)
메인 화면을 쓰지 않는다. 매일 수집도 날짜별 목록 `past?day=<어제>`로, 날짜당 페이지 수는 `sources.yaml` 설정값(기본 1 = 그날 점수 상위 약 20건). 백필도 같은 방식. 점수와 댓글 수 저장은 그대로

## 라벨 파일 → 결정(2026-10-08)
재측정 뒤 최신 출력으로 다시 만든다. 출력이 이전과 같은 행만 기존 라벨을 보존하고, 바뀐 행은 비운다
