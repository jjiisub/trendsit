# S0 리뷰 반영 (S1의 1a에 함께)

> 작성: 2026-10-07. S0 PR #1은 설계 세션 리뷰 후 같은 날 병합됐다(리뷰 코멘트는 PR #1에 있음). 아래는 리뷰에서 나온 지적 중 S1 1a에서 `S0_ADDENDUM.md`와 함께 처리할 것이다. 예산은 1a 몫(0.05달러) 안에서, 대부분 LLM 호출이 없다.
> 리포트(`reports/S1_report.md`)의 1a 체크리스트에 R1~R6을 따로 적는다.

## 1. 고칠 것

### R1 자료 태그 탈출 방지 (보안, 중간)
- 지금 `wrap_data`는 `</data`, `<data`만 소문자로 바꿔서 `</DATA>`, `</Data >`가 그대로 통과한다
- `S0_ADDENDUM.md` 1.3의 `render_data`에서 자료 안의 `<`를 모두 `&lt;`로 바꾼다(태그 이름 목록에 기대지 않음). 도구 결과를 붙이는 경로도 같은 함수를 쓴다
- 테스트(P3에 추가): `</DATA>`, `</Data >`, `</document >`, `<DOCUMENT id="x">`가 들어간 입력이 태그 밖으로 나가지 않음

### R2 채점자 md를 역할과 무관하게 (중간)
- 지금 `eval/judge.md` 본문에 repo_oneliner 채점표가 들어 있고, 같은 채점표가 `includes`로 한 번 더 붙는다. S2부터 다른 역할을 채점하면 "대상: repo_oneliner"가 남는다
- `judge.md` 본문은 역할 무관한 판정 지침만(질문마다 critique → pass, "길이나 자신감이 아니라 근거와의 일치로 판단한다"). 역할별 질문과 대상 설명은 `eval/rubrics/<역할>.md`에만 두고 includes로 붙인다
- `S0_ADDENDUM.md` 1.7 개편과 같이 한다

### R3 도구 예외를 결과로 (낮음, S3 전에 필요)
- 지금 `execute_tool`은 `ToolRejected`만 잡는다. S3에서 실제 fetch 도구가 네트워크 예외를 내면 루프 전체가 멈춘다
- 도구 함수에서 난 그 밖의 예외는 `오류: 도구 실패(<예외 이름>): <메시지 200자>`를 모델에게 결과로 돌려주고, 해당 tool step에 `error`, `attention=1`을 남긴다. `BudgetExceeded`는 지금처럼 위로 올린다
- 테스트: 예외를 내는 가짜 도구를 등록해도 루프가 이어지고 step에 error가 남음

### R4 nullable 도구 인자 정규화 (낮음)
- S0 리포트 6장: 무료 모델이 nullable 인자에 문자열 `"None"`을 자주 넣음(lookup_agent 5건에서 14회 거부). 로컬 소형 모델에서도 예상됨
- 도구 인자 검증 직전, 스키마상 null을 허용하는 칸의 값이 `"None"`, `"null"`, `""`이면 null로 바꾼다(코드 규칙). 바꾼 사실은 tool step의 detail에 `normalized: [칸 이름]`으로 남긴다
- null을 허용하지 않는 칸은 건드리지 않는다. 테스트로 두 경우 모두 확인

### R5 비밀 검사 범위 좁히기 (참고)
- 지금 A9의 `git grep`이 `data/` 전체를 뺀다. 추적 중인 `data/make_data.py`, `data/trendsit-example.json`도 검사에서 빠진다
- 제외 대상을 git이 무시하는 실행 산출물(`data/trendsit.db*`, `data/cache/`, `data/budget_state.json`, `data/prices.json`)로 좁힌다. `verify_s0.sh`를 고치는 것은 기준을 강화하는 쪽이라 허용

### R6 역할 md 검사 범위 정하기 (명확화)
- `S0_ADDENDUM.md` 1.5의 검사는 `roles/*.md`와 `eval/judge.md`에 적용한다
- 고정 섹션 6개(`## 목표` / `## 입력` / `## 판단 기준` / `## 출력` / `## 막혔을 때` / `## 예시`)가 이 순서로 있으면 되고, 그 사이에 다른 섹션(예: 도구 에이전트의 `## 도구`)이 있어도 된다
- `lookup_agent.md`(테스트용 도구 에이전트)도 이 틀로 다시 쓴다. 예시 3개: 깊이 2에서 찾음 / 깊이 상한 안에 없어서 doc_id=null(빈칸이 맞는 경우) / 함정(깊이 4 문서를 parent 없이 바로 읽으려는 경우)

## 2. 유지할 것 (S0에서 정한 것, ADDENDUM 예시에 없더라도 지우지 않음)
- 역할 md 앞부분의 `input:`(입력 클래스 이름). ADDENDUM과 prompt_guide의 앞부분 예시에는 없지만 CLI 입력 검증에 필요하다
- 에이전트의 최종 답은 자동으로 붙는 `finish` 도구로 제출
- `--no-cache`는 읽기만 끄고 새 응답은 저장
- 깊이 판정은 모델이 준 parent만 믿지 않고 실제로 읽은 문서의 링크만 인정
- 단계 사용액 = max(키 기준, 실행 기록 합)
