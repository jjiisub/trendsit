# 문서 작성 에이전트 가독성·도식화 가이드 요약 (2026-10-07)

원문: 설계 세션 문서 "문서 작성 에이전트의 가독성·도식화 가이드 — TrendsIT 작성자 적용". 작성자 지침(`writer_draft.md`) v2에 반영됨.

## 결론
형식은 정보의 모양이 정한다. 기본은 문장이고, 도식은 글로 읽는 것보다 빠를 때만 쓴다. 문서 작성 에이전트 전용 공식 표준은 없지만 가져다 쓸 조각은 충분하다.

## 근거 요지
- Anthropic 공개 시스템 프롬프트: 최소한의 형식. 보고서는 문단 위주, 목록은 여러 측면일 때만, 항목은 1~2문장 이상
- Anthropic 프롬프트 모범 사례: "하지 마라" 대신 "이렇게 하라". 프롬프트 문체가 출력에 영향. 형식 억제 문구는 최신 모델에서 필요한 구조까지 눌러버릴 수 있음
- FT Visual Vocabulary: 데이터 관계 9가지로 도식 선택(TrendsIT는 크기, 순위, 시간 변화, 흐름 정도) / Datawrapper: 정확한 값, 찾아보기, 두 방향 비교는 표, 패턴과 이상치는 차트
- NN/g 역피라미드: 결론 먼저
- 평가: G-Eval 4축(관련성, 일관성, 충실성, 유창성), FActScore(원자 사실 지지율), VisEval(유효성, 적법성, 가독성. 코드 검사 + 멀티모달 채점, 사람과 상관 0.843. 채널 3개 이상 도식은 모든 모델에서 품질 하락)
- ROUGE 같은 단어 겹침 지표는 사람 판단과 상관 낮음(OpenAI 쿡북). LLM 채점자는 LLM 글을 후하게 봄 → 주 1회 사람 확인

## 형식 선택 순서
1. 같은 단위 비교가 쟁점(값 3개 이상, 또는 2개 전후 차이가 summary에 나옴) → 수치 막대
2. 날짜 다른 사건 3개 이상(2개는 흐름이 쟁점일 때만) → 사건 흐름
3. 영상 특정 시각 인용 → 영상 타임라인
4. 정확한 값 찾아보기, 두 방향 비교 → 표(TrendsIT MVP 화면에는 없음)
5. 그 외 → 문장

## 과도한 도식의 신호
값이 2개뿐인 막대 / 단위나 대상이 섞인 도식 / 같은 내용을 두 번 / 제목만 있고 결론이 없는 도식(제목에 발견을 쓸 것) / 본문 어디에도 언급되지 않는 도식 / 채널 3개 이상 또는 장식용 색 / 몇 단어짜리 목록 연발

## TrendsIT에 더한 것
- 도식 판단 라벨 세트(토픽 20개, 사람 라벨) → 누락률, 남발률을 따로 계산. 목표 남발 0, 누락 20개 중 1 이하
- 렌더 가독성 검사(Playwright로 SVG 넘침, 겹침, 단위) + 주 1회 스크린샷 멀티모달 채점
- 검수자 질문 "이 도식을 빼면 잃는 것이 있나?"(overuse) / 누락 경고와 쌍(missing_diagram)
- 구현 모델로 토픽 5개를 먼저 돌려 선택 칸 공백 비율 확인 후 문구 조정
- 첫 실행 후 예시를 실제 출력으로 교체
