# TrendsIT 디자인 시스템 v1

S6에서 정한 화면 규칙이다. 파일은 세 개다.

| 파일 | 내용 |
|---|---|
| `tokens.css` | 색, 서체, 글자 크기, 줄 간격, 간격, 크기, 움직임, 쌓임 순서 변수 |
| `trendsit.css` | 컴포넌트. `tokens.css` 변수만 쓴다 |
| `DESIGN.md` | 이 문서. 규칙과 이유 |

불러오는 순서는 `@font-face` → `tokens.css` → `trendsit.css`다. 정적 HTML과 CSS만 쓰고 JS는 쓰지 않는다. 외부 요청은 없다(Pretendard 직접 호스팅).

## 1. 원칙

1. **읽는 도구가 먼저다.** 월요일 아침 5분 안에 이번 주 흐름을 파악하는 것이 목표다. 장식보다 위계, 위계보다 읽기 쉬움이 먼저다.
2. **두 모드, 한 벌의 토큰.** 홈·주차·토픽은 읽기 모드, 소스·키워드·실행 기록은 관리 모드다. 관리 모드는 같은 토큰으로 밀도와 글자 크기만 줄인다.
3. **무채색 + 형광 하나.** 색만으로 뜻을 전하지 않는다. 상태(확인 필요, 실패, 대기)는 항상 글자로 쓰고, 주의가 필요한 상태에만 테두리 배지를 쓴다.
4. **서체는 하나, 굵기는 둘.** Pretendard 400과 500만 쓴다. 위계는 크기와 색으로 먼저 만든다.
5. **모든 문장은 출처로 이어진다.** 인용 번호는 앞 어절과 붙어 함께 줄바꿈되고, 누를 영역은 24px 이상이다.
6. **움직임은 두 곳뿐이다.** 인용 툴팁의 지연, PC 상세의 미니 바 등장.

### 간격과 크기

- **간격:** `--sp-1` 4부터 `--sp-12` 48까지 쓴다(4, 8, 12, 16, 20, 24, 28, 32, 40, 48). 4의 배수만 쓰고, 예외는 1px 선과 2px 포커스 테두리다.
- **누를 영역:** `--target` 24px(인용 번호, 툴팁 링크)와 `--target-lg` 44px(내비, 탭, 뒤로, 이전·다음)를 쓴다.
- **반경:** `--radius-s` 4(배지, 막대, 코드)와 `--radius-m` 8(도식, 툴팁, 관리 화면 강조 줄)만 쓴다. 8보다 큰 반경은 쓰지 않는다.
- **폭:** `--maxw` 720px(읽기 한 열, 관리 화면은 PC에서 960px)을 쓴다. `--gutter`는 모바일 20px, 1024px 이상에서 32px이다.
- **앵커 여유:** `--sticky-offset` 72px. 앵커로 이동했을 때 미니 바에 가리지 않게 한다.

### 움직임과 쌓임

- **툴팁:** `--tip-in` .15s(지나가기만 할 때 깜빡이지 않게), `--tip-linger` .6s(벗어나도 유지), `--tip-fade` .15s.
- **움직임 줄이기:** `prefers-reduced-motion`이면 페이드 없이 사라진다.
- **쌓임 순서:** `--z-tabs` 2, `--z-mini` 3, `--z-tip` 10.

## 4. 컴포넌트

### 4.1 공통

- **`.wrap`:** 가운데 한 열(`--maxw`)에 좌우 여백 `--gutter`를 둔다.
- **`.nav`:** 상단 내비. 워드마크와 메뉴가 같은 회색이고, 현재 페이지만 제목색에 2px 밑줄을 쓴다. 각 링크는 높이 44px이다.
- **`.meta`:** 14px 회색, 표 숫자. 메타 항목은 `" / "`(`<span class="sep">/</span>`)로 나눈다. 가운뎃점 이어 붙이기는 쓰지 않는다.
- **`.check`:** "확인 필요"처럼 주의가 필요한 상태에만 쓴다. 13px, 1px 회색 테두리, 반경 4, 글자는 제목색이다.
- **`mark.hl`:** 형광 밑칠(아래 44%). 굵기와 글자색은 바꾸지 않는다. 개수와 의미는 S5 작성 규칙을 따른다.
- **`:focus-visible`:** 2px 제목색 테두리, 2px 떨어뜨림.

| 카드 | 카드 안 카드, 섹션 전체를 떠 있는 카드로, 색 좌측 테두리, 반경 8px 초과 |
| 움직임 | 섹션 페이드인, 모든 요소의 hover 전환, `transition: all` |
| 색 | 그라디언트(형광의 단색 밑칠은 예외), 글로우, 토큰 밖 색 |
| 글자 | 음수 자간, 대문자 라벨, 뷰포트 비례 글자 크기, 제목 안 `<br>`, 라벨·제목 끝 마침표 |
| 메타 | "A · B · C" 가운뎃점 이어 붙이기, 단위 없는 숫자("+5.6k" 대신 "이번 주 별 +5.6k") |
| 기타 | hover에만 있는 정보(툴팁 내용은 출처 목록에 모두 있음), `title` 속성 |

그림자는 툴팁 하나에만 있다(떠 있는 층을 구분하기 위해). 빼도 1px 테두리로 구분된다.

## 6. 측정 관문(새 화면·컴포넌트마다)

Chromium 375·768·1280에서 잰다(`drafts/shoot.py`의 `GATE_JS`).

1. 가로 넘침 0
2. 글자 대비 4.5:1(24px 이상 제목은 3:1)
3. 본문 16px 이상, 줄 간격 1.5 이상
4. 형광 구절이 단어 중간에서 끊긴 곳 0
5. 토픽 핵심 포인트가 375×812 첫 화면 안에서 시작
6. 인용 번호 24×24 이상
7. 계산된 색이 모두 토큰 안
8. 선언한 서체가 실제로 로드됨
9. 제목 단계 건너뛰기 0, `title` 속성 0

## 7. 바꾸는 방법

- 새 값이 필요하면 `tokens.css`에 먼저 넣고 이 문서 표를 고친 뒤 컴포넌트에서 쓴다.
- 새 컴포넌트는 5장(피할 것)과 6장(관문)을 통과해야 한다.
- 다크 모드는 아직 없다. 넣을 때는 `--c-*`만 다시 정의하고 컴포넌트는 고치지 않는다.

## 8. 결정 기록(S6)

| 결정 | 버린 안과 이유 |
|---|---|
| 리드 토픽은 순서로만 구분 | 테두리 카드, 큰 글자(사용자가 거부) |
| 홈은 탭으로 토픽/레포 분리 | PC 2열(토픽 + 레포 열)은 "완전 별로", 고정 바로가기는 선택 표시가 없어 어색함 |
| Pretendard 400·500 | IBM Plex, 세리프, Jua, Gowun, Wanted Sans 조합 비교 끝에 얇고 깔끔한 쪽 선택 |
| 상세 PC는 한 열 + 미니 바 | 오른쪽 출처 열, 여백 각주, 도식 옆 배치 |
| 인용 툴팁 + 지연 닫힘 + 하나만 | 즉시 사라지는 툴팁은 카드 안 링크를 누르기 어려움 |
| 출처 → 인용 백링크 없음 | 출처와 인용이 일대다라 출처 목록이 복잡해짐 |
| PC 본문 폭 720px 유지 | 본문만 576px로 줄이는 안은 도식·출처와 오른쪽 끝이 어긋남 |
