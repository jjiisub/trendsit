주요 토픽 10

  1. 판단 모델 경쟁 본격화, 결정 API와 추론형 판단

    OpenAI가 Luna 기반 Decision API를 공개했고, 판단 전에 추론을 넣은 Jeeves는 정확도를 크게 올렸다. 쟁점은 정확도를 얻는 대신 지연이 늘어나는 맞교환이다.

    글 3 / 영상 1 / 레포 2 / 후속

  2. 코딩 에이전트 하네스, 오래 돌고 끊겨도 이어서

    터미널 코딩 에이전트 Pi가 1.0을 냈고, 중단된 작업을 이어 가는 Pi Durable도 함께 공개됐다. 경쟁 지점이 에이전트를 오래 돌리는 바깥 틀(하네스)로 옮겨 가고 있다.

    글 5 / 레포 1 / 후속

  3. 평가 비용 줄이기, 작은 판단 모델로 1차 채점하고 애매한 것만 큰 모델에 넘기는 2단계 채점

    작은 판단 모델이 먼저 채점하고 확신이 낮은 답만 큰 모델에 넘기는 2단계 채점 사례가 여러 곳에서 나왔다. 한 팀은 채점 비용을 약 6분의 1로 줄이면서 사람 판정과의 일치율은 2%p만 잃었다.

    글 7 / 영상 2 / 레포 3

  4. 검색 저장소, 벡터 DB 하나로는 부족하다

    그래프, 벡터, 전문 검색을 한 파일에 담은 LatticeDB가 나왔고, Turbopuffer는 벡터 인덱스를 보조로 내리는 v3 설계를 밝혔다. 흐름은 의미 검색과 키워드 검색을 함께 쓰는 쪽이다.

    글 3 / 레포 2

  5. 작은 코딩 모델, 노트북에서 돌리는 자동완성

    1.5B~7B 크기의 코딩 모델이 노트북에서 자동완성을 맡는 사례가 늘었다. 가장 큰 Kestrel-7B는 클라우드 기준 모델과 통과율 8%p 차이까지 좁혔다.

    글 2 / 영상 1 / 레포 2 / 확인 필요

  6. 영상과 음성, 에이전트가 직접 보고 듣는다

    영상을 15초 구간으로 나눠 장면과 화면 속 글자까지 따로 기록하는 MCP 서버가 나왔고, 기기 안에서 전사하는 녹음 앱도 여럿 공개됐다.

    글 4 / 영상 1

  7. MCP 서버 목록 정리, 검증 표시와 권한 범위

    흩어져 있던 MCP 서버 목록을 한곳에 모으고 검증 여부와 요구 권한을 함께 보여 주는 시도가 이어졌다. 핵심은 설치 전에 서버가 무엇을 읽고 쓰는지 보이게 하는 것이다.

    글 3 / 레포 1

  8. 에이전트 생산성, 재 보면 체감과 다르다

    셀프테스트는 통과했지만 실데이터 261편 중 6편만 맞춘 자동화 실패기와, AI를 쓴 과제가 오히려 19% 오래 걸렸다는 METR 실험 정리가 같은 주에 나왔다. 두 글의 결론은 같다. 만든 직후 실데이터로 한 번 돌려 볼 것.

    글 2

  9. 로그인된 브라우저를 쓰는 에이전트, 그리고 보안 점검

    로그인된 Chrome을 에이전트에 그대로 연결하는 BrowserSkill과, AI 인프라와 에이전트를 점검하는 AI-Infra-Guard가 공개됐다. 브라우저 연결은 편리한 만큼 권한도 그대로 넘어간다.

    글 3 / 레포 2 / 후속 / 확인 필요

  10. CLI 출력을 표로, 사내 도구 정리 경험

    한 팀이 사내 CLI 30여 개의 출력을 같은 표 형식으로 맞춘 경험을 공유했다. JSON 출력 옵션을 먼저 붙이고 표는 그 위에 그린 것이 핵심이다.

    글 1
