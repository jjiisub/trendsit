# TrendsIT 화면 디자인 명세 (최종안 v2)

> 정적 예시 사이트와 이후 실제 화면이 따를 규칙이다. 시각 기준은 `mockups/` 폴더의 HTML 8개다(홈 모바일, 토픽 모바일, 홈 PC, 소스, 키워드, 실행 기록 3단). 홈과 토픽 목업의 글은 디자인 단계 샘플이고, 관리 화면 목업은 예시 데이터로 만들었다. 실제 내용은 모두 `data/trendsit-example.json`에서 온다.
> 바탕: 당근 SEED Design(@seed-design/css 3.x, Apache-2.0)의 색과 반경 값.
> 목업과 이 문서가 다르면 이 문서를 따른다. 예: 리드 카드 위 문구는 목업의 "이번 주 가장 많이 교차 확인된 토픽" 대신 "이번 주 핵심 토픽", 목업의 "밑줄 친 수치" 안내 줄은 넣지 않는다.

## 1. 원칙
- **차분한 읽기 도구.** 화면 전체는 무채색. 유채색은 형광 밑줄(핵심 내용) 하나뿐
- **강조는 한 곳에만.** 시그니처 요소는 형광 밑줄. 다른 장식(배지 남발, 그림자, 그라데이션, 애니메이션)은 쓰지 않는다
- **블로그처럼 읽히는 목록.** 카드는 홈의 리드 토픽 1개에만. PC에서도 카드 그리드를 쓰지 않는다
- **모든 문장은 출처로 이어진다.** 토픽 페이지의 핵심 포인트와 도식에는 출처 표시가 있다

## 2. 쓰지 않는 것 (기본값 회피 목록)
크림/미색 배경 + 세리프 + 테라코타 조합 / 검정 배경 + 형광 한 색 / 신문식 가는 선 레이아웃 / 둥근 회색 그림자 카드 그리드 / 가운데 히어로 + 기능 카드 3개 / 제목 속 한 단어만 기울임이나 색 / 대문자 소제목 / 모노스페이스 라벨 / 01, 02, 03 번호 / 알약 모양 버튼 / 링크 끝 화살표 / Inter, Roboto, 시스템 기본 글꼴 / 보라 그라데이션 / 섹션마다 페이드업

### 반경, 간격
- 반경: 배지 4px(r1), 막대 3~4px, 리드 카드와 도식 바탕 12px(r3). 둥근 알약 모양은 쓰지 않는다
- 좌우 여백: 모바일 20px, PC 본문 폭 1080px 가운데 정렬
- 섹션 간격: 토픽 페이지 섹션 위 26px, 목록 항목 위아래 18px(PC 22px)

## 4. 형광 밑줄 규칙 (시그니처)
- 모양: `background: linear-gradient(transparent 56%, #ffd5c0 56%); padding: 0 2px; font-weight: 500; color: 본문색`
- 뜻: **그 토픽의 핵심 결론이나 키워드.** 데이터의 `==텍스트==`가 그대로 형광 밑줄이 된다
- 관리 화면(소스, 키워드, 실행 기록)에서는 뜻이 **"지금 사람이 봐야 할 것"**: 수집 실패, 끌지 정할 소스, 승인 대기 별칭 후보, 검수 반려, 확인 필요. 화면당 2~4개 이내
- 개수: 홈 요약은 토픽당 최대 1개 / 토픽 페이지는 개요 1개 + 핵심 포인트 항목당 최대 1개, 페이지 전체 3~4개 이내
- 쓰지 않는 곳: 제목, 출처, 타임라인, 개념 풀이, 레포 설명, 버튼
- 슬라이드에서만 나온 수치는 형광으로 구분하지 않는다. 문장 안에 "발표 슬라이드 기준"이라고 쓰고, 도식 아래 출처 줄과 영상 타임라인의 슬라이드 표시로 알린다

## 5. 공통 요소

### 상단
- 모바일: 1줄 워드마크(왼쪽) + "예시 데이터"(오른쪽, 12px 회색) / 2줄 텍스트 탭(브리핑, 소스, 키워드, 실행 기록), 아래 1px 구분선
- 활성 탭: 글자 700 + 아래 2px #1a1c20 밑줄. 비활성: #868b94
- PC: 한 줄에 워드마크 + 탭 + 오른쪽 "예시 데이터"
- 토픽 페이지 상단(모바일): 왼쪽 "10월 1주차 브리핑으로" 텍스트 링크, 오른쪽 워드마크. 화살표 기호를 붙이지 않는다

### 채널 막대
- 가로 막대를 채널 비율로 나눔(글, 영상, GitHub 순서). 주간 전체는 높이 8px 전체 폭, 토픽별은 높이 6px 폭 96px, 반경 3~4px
- 범례: 8px 사각형 + "글 41" 같은 라벨, 12px

### 리드 토픽 카드 (홈, 1개)
- 대상: 주차의 rank 1 토픽(`lead: true`)
- 테두리 1px #dcdee3, 반경 12px, 그림자 없음, 안쪽 여백 18px(PC 24px 26px)
- 위에서부터: "이번 주 핵심 토픽"(12px, #555d6d, 500) / 제목 / 요약(형광 1개) / 메타(채널 막대 + "글 3 / 영상 1 / 레포 2" + 후속이면 "지난 흐름의 후속")

### 토픽 목록 항목
- 카드 아님. 위아래 여백 + 아래 1px #eeeff1 구분선
- 제목 / 요약 1~2문장(최대 3문장) / 메타 줄(채널 막대, 채널 수 라벨, "지난 흐름의 후속", 확인 필요 문장이 있으면 "확인 필요 1")
- 항목 전체가 토픽 페이지 링크. 호버 시 제목에 회색 밑줄

### 레포 항목
- 3줄: ① 이름(14px 700) + 오른쪽 7일 별 증가(13px 500) ② 하는 일 한 문장(13px, #2a3038) ③ 신호 / 메모(있을 때) / 관련 토픽(있을 때), 12px #868b94. 예: "급상승 / '검색 저장소' 토픽과 관련", "릴리스 / v4.6.0 / '로그인된 브라우저' 토픽과 관련"
- 신호 "확인 필요"만 배지: 1px #b0b3ba 테두리, 반경 4px, 검정 글자 500, 좌우 5px. 별 증가 숫자는 회색
- 링크: GitHub. 가상 레포(`fictional: true`)는 링크 없음

### 배지와 링크
- 배지는 "확인 필요"와 "승인 모드" 두 종류만(같은 모양)
- 버튼(관리 화면): 높이 32~36px, 반경 8px. 주 버튼은 #1a1c20 바탕 흰 글자, 보조 버튼은 1px #d1d3d8 테두리. 예시 사이트에서는 비활성 + "예시 사이트라 동작하지 않아요"
- 경로 줄(실행 기록): "주차별 / 10월 1주차 / 10.5 주간 발행" 13px #868b94, 링크 부분만 #555d6d + 회색 밑줄
- 알림 상자(소스의 "확인할 것"): 바탕 #f7f8f9, 반경 12px, 안쪽 12px 14px. 페이지당 1개
- 텍스트 링크: 검정 글자 + `text-decoration-color: #d1d3d8; text-underline-offset: 4px`, 호버 시 밑줄 #1a1c20
- 누르는 영역 최소 44px 높이

## 6. 화면

### 6.1 브리핑 홈 `/` (최신 주차), `/week/<주차id>/` (지난 주차)
- 순서: 상단 → 주차 헤더(주차 이름, "9.28 ~ 10.4 / 소스 55건에서 토픽 6개", 주간 채널 막대 + 범례) → 리드 카드 → 토픽 목록 → 관심 분야 레포 → 주차 이동("지난 주차: 9월 4주차") → 실행 시각("발행 10.5 07:00 / 다음 발행 10.12 07:00")
- PC(1024px 이상): 1080px 가운데. 왼쪽 본문 680px(주차 헤더, 리드 카드, 토픽 목록) / 간격 64px / 오른쪽 336px(이번 주 수집 막대와 범례, 관심 분야 레포, 주차 이동, 실행 시각). 오른쪽 열은 `position: sticky; top: 24px`
- 맨 아래 작은 회색 안내: 데이터의 `meta.notice`

### 6.2 토픽 페이지 `/topic/<id>/`
- 순서: 헤더(제목, 채널 막대 + 라벨, "N개 채널에서 확인", 후속이면 관련 토픽 링크) → 개요 → 소스 연결도 → 핵심 포인트 → 도식(데이터에 있는 것만) → 핵심 개념 → 소스별로 더한 것 → 출처
- 핵심 포인트: 5px 회색 점 + 문장 + 문장 끝 출처 번호(작은 회색 [1], 출처 목록으로 이동). `check: true`면 문장 끝에 "확인 필요" 배지
- PC: 1080px 가운데. 본문 680px / 오른쪽 336px에 출처 목록을 고정(sticky). 모바일은 출처가 맨 아래
- 분량: 보통 1~1.5화면 스크롤. 소스가 하나뿐인 토픽은 짧게

### 6.3 소스 `/sources/` (목업 `sources-mobile.html`)
- 순서: 제목 "소스 10개" + "켜짐 9 / 꺼짐 1. 10월 1주차에 55건 모아 토픽에 29건 썼어요." → 알림 상자 "확인할 것 N개"(형광) → 요일 머리(월~일) → 채널 묶음(글, 영상, GitHub) → 범례 → "소스 추가"(비활성)
- 채널 묶음 머리: 13px 700 #555d6d, 오른쪽 "6개 / 41건"
- 소스 줄: 왼쪽 이름(15px 500) + 메타("RSS / 26건, 토픽에 20건 / 실패 1회", 12px 회색) / 오른쪽 7일 막대
- 7일 막대: 하루 1개, 폭 6px, 간격 4px, 높이 = 건수 × 3px(최소 4, 최대 22), #2a3038. 0건은 높이 2px #dcdee3, 실패(None)는 6 × 22 점선 칸(1px dashed #868b94)
- 꺼진 소스: 이름 회색, 오른쪽 "꺼짐", 메타 자리에 `note`
- "확인할 것" 만드는 규칙(예시 데이터 기준): 이번 주 `failed_days > 0`인 소스 / 2주 연속 `used_in_topics == 0`인 켜진 소스 묶음 → "끄거나 키워드 필터를 붙일지 정해 주세요"
- PC: 본문 680px 1열, 1080px 틀 안에서 왼쪽 정렬(브리핑 본문 열과 같은 시작선. 관리 화면은 모두 같음. 1차 리뷰 반영 2026-10-06)

### 6.4 키워드 `/keywords/` (목업 `keywords-mobile.html`)
- 순서: 제목 "키워드 8개" + 설명 → "확인할 별칭 후보 N개"(대기 후보, 오른쪽에 `run_id` 실행의 시각 "10.5 07:00 실행에서 나옴") → "최근 거절" 한 줄 → "키워드와 별칭"(범례: 확정 실선, 후보 점선, 거절 점) → 키워드 가지 목록(이번 주 언급 많은 순, 같으면 `items` 순서 유지) → "키워드 추가"(비활성)
- 후보 항목: 별칭(16px 500, 형광) / "<키워드>의 별칭으로 묶을까요?" / 이유와 제안자(12px) / 근거 글 링크(12px 회색 밑줄) / 승인(주 버튼), 거절(보조 버튼)
- 키워드 가지: 키워드 이름(16px 700) + 오른쪽 "이번 주 14회 / 지난주 +4" / 왼쪽 1.5px 세로선에서 별칭마다 14px 가로선
  - 확정 별칭: 실선 #d1d3d8, 글자 #2a3038
  - 대기 후보: 점선 #868b94 + "후보"(12px 회색). 가지에서는 형광을 쓰지 않는다(위 후보 목록과 중복)
  - 거절 후보: 점선(dotted) #d1d3d8 + 취소선 회색 글자 + "거절, 다른 대상"

### 6.5 실행 기록 3단 (목업 `runs-weeks-mobile.html`, `runs-week-mobile.html`, `runs-detail-mobile.html`)
메뉴의 "실행 기록"은 **메인(이번 주차)**으로 바로 열린다. 위로는 주차별 목록, 아래로는 실행 1건 상세.

| 단계 | 주소 | 데이터 |
|---|---|---|
| 메인: 이번 주차 | `/runs/` (= 최신 주차), `/runs/<주차id>/` | `run_weeks[]` 중 그 주, `runs[]` 중 `week`가 같은 것 |
| 상위: 주차별 | `/runs/weeks/` | `run_weeks[]` 전체 |
| 하위: 실행 1건 | `/runs/<주차id>/<실행id>/` | `runs[]`의 한 항목 |

- **메인**: 경로 줄 "주차별 / 10월 1주차" + 오른쪽 "지난 주차: 9월 4주차" → 제목 "10월 1주차 실행 기록" + "9.28 ~ 10.4 / 모델 ... / 실행 8번" → **봐야 할 판단**(그 주 runs의 `steps[].attention == true` 전부. 형광 + "10.5 07:11 검수자 / 판단 기록 보기" 링크. 10월 1주차는 3개) → **브리핑이 나오기까지** 단계 레일(수집 → 묶기와 과거 대조 → 선별 → 작성 → 검수 → 발행, 각 단계 숫자와 한 줄 설명) → **이 주의 실행 N번** 목록(시각, 종류, 요약 / 오른쪽 상태 "정상"/"일부 실패"와 "판단 n개")
  - 단계 레일: 왼쪽 점 10px(#868b94, 마지막 #1a1c20) + 세로선 2px #eeeff1, 단계 이름 14px #555d6d, 숫자 15px 700 오른쪽 정렬
  - 레일 숫자는 그 주 weekly 실행의 `counts`와 `run_weeks`에서 가져온다(수집 = run_weeks.collected, 후보 = candidates, 선별 = counts.selected, 초안 = selected, 검수 = review.passed_first와 rejected, 발행 = published)
- **메인 세부 규칙**
  - "지난 주차" 링크는 그 주에 페이지가 있을 때만(`run_weeks[].detail`이 true). 없으면 대신 "주차별 목록" 링크
  - 실행 목록 오른쪽 "판단 n개"는 `runs[].decisions`
  - 봐야 할 판단 줄: 단계 `text`를 그대로 쓰고, 첫 `:` 앞부분을 형광. `:`가 없으면 `'확인 필요'` 부분을 형광. 아래 작은 줄은 "10.5 07:11 검수자 / 판단 기록 보기"(weekly는 `t`, nightly는 실행 시각)
  - 목업의 "검수 반려 1회:" 같은 머리말은 예시일 뿐, 위 규칙을 따른다
- **상위**: 경로 줄 "실행 기록 / 주차별" → 제목 + 요약 한 줄("3주 동안 발행 15개. 검수 반려는 3회, 0회, 1회였어요.") → 주별 작은 막대(발행 토픽 #b0b3ba, 검수 반려 #2a3038, 같은 눈금) → 주차 목록(주차 이름 + `approval_mode`면 "승인 모드" 배지 / 수집, 후보, 발행 / 매일 수집 횟수와 실패, 반려, 확인 필요 / `note`). `detail: false`인 주는 "단계별 기록은 예시 데이터 범위 밖"이라 적고 링크하지 않는다
- 상위 막대는 왼쪽부터 오래된 주, 목록은 최신 주가 위
- **하위**: 경로 줄 "주차별 / 10월 1주차 / 10.5 주간 발행" → 제목 → 정보 표(시작, 걸린 시간, 모델, 입력, 결과) → 역할 필터 글자 탭("전체 6 / 편집장 3 / ...", 정적 사이트에서는 "전체"만 동작해도 됨) → 판단 로그(시각 `t` 40px 열 / 역할 12px 회색 / 내용 14px). 반려, 확인 필요는 형광
  - 반려 상세(`steps[].detail`): 회색 바탕 상자(#f7f8f9, r12)에 "초안 / 근거 / 수정" 세 줄. 수정 줄은 500
  - 매일 수집(nightly) 실행은 `t`가 없으니 시각 열 없이 역할과 내용만, `errors[]`는 맨 위에 형광 한 줄
  - 정보 표: weekly는 입력 "이번 주 수집 {run_weeks.collected}건, 후보 토픽 {counts.candidates}개", 결과 "토픽 {counts.published}개 발행, 근거 id {counts.evidence_ids}개" / nightly는 입력 "켜진 소스 {켜진 소스 수}개", 결과는 `summary`
  - 맨 아래 링크: "이 실행이 만든 10월 1주차 브리핑 보기"(weekly만, `/week/<주차id>/`), 같은 주의 바로 앞, 바로 뒤 실행(`at` 순, 있는 것만)

## 7. 도식
도식은 데이터에 있는 것만 그린다. 숫자는 데이터 값만 쓴다. 모든 도식 아래에 캡션(12px 회색, "출처: ...")을 단다. 가로 스크롤 없이 폭에 맞춘다. 인라인 SVG 또는 HTML/CSS로 만든다(외부 차트 라이브러리 없음).

### A 소스 연결도 (항상)
- 바탕 #f7f8f9, 반경 12px. 가운데 검정 둥근 사각형 "이번 토픽"(흰 글자 12px 700)
- 소스 노드를 가운데 둘레에 고르게 배치(타원 위 등간격). 노드: 지름 12px 원, 채널 회색으로 채움(GitHub는 #d1d3d8 + #868b94 테두리). 라벨 11px "글 / 제목 앞부분 14자"
- 선: 기본 1.5px #d1d3d8. 도식의 수치 근거가 된 소스(`diagrams[].ref`)는 2.5px #2a3038
- 후속 토픽이면 아래쪽에 빈 원 + 점선 + "9월 4주차 ..." 라벨(지난 토픽 링크)
- 노드는 원본 링크. 아래 캡션 "굵은 선은 수치를 직접 제공한 소스, 점선은 이어지는 지난 토픽이에요."
- 크기: 모바일 350 × 210, PC 680 × 240

### B 수치 막대 (`type: bars`)
- 항목마다 한 줄: 라벨(42~110px, #555d6d) / 막대(높이 14px, 바탕 #f3f4f5, 반경 4px) / 값(500)
- 채움: 기준 항목 #b0b3ba, `emphasis: true` 항목 #2a3038
- 막대 길이는 항목 중 최댓값 기준 비율. 값 자리에는 `display`가 있으면 그 글자("119 (19% 더 걸림)"), 없으면 값 + `unit`. 라벨 열 폭은 가장 긴 라벨에 맞추고, 모바일에서 값 글자가 길면 막대 아래 줄로 내린다
- `example: true`면 캡션에 "가상 수치" 포함

### C 영상 타임라인 (`type: video`)
- 세로 선 2px #eeeff1 + 점 10px(#d1d3d8). 슬라이드 표시(`slide: true`) 점은 #2a3038, 설명 글자 500
- 시각 글자(13px 500 #555d6d, 회색 밑줄)는 원본 영상의 그 시각 링크(`?t=` + 데이터의 `sec`). 예시 영상은 링크 없이 글자만
- 위에 영상 제목과 길이, "예시 영상" 표시

### D 사건 흐름 (`type: events`)
- 모바일: 세로 타임라인(날짜 12px 회색 / 사건 14px). PC: 같은 세로형을 본문 폭으로
- 다른 토픽(`topic_id`)에서 온 사건은 그 토픽 페이지 링크, 같은 토픽 출처(`ref`)는 출처 번호

## 8. 반응형
- 640px 미만: 모바일 1열 / 640~1023px: 1열, 본문 최대 680px 가운데 / 1024px 이상: PC 2열
- 도식은 폭에 맞춰 그린다(SVG `viewBox` + `width: 100%`)

## 9. 접근성과 기타
- 본문 대비 4.5:1 이상(회색 #868b94는 12px 보조 글자에만)
- 형광 밑줄은 색 외에 굵기(500)로도 구분된다
- `lang="ko"`, 페이지마다 `<title>`("TrendsIT", 토픽 페이지는 "토픽 제목 | TrendsIT")
- 다크 모드는 이번 범위가 아님(이후)
