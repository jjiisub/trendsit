# 도식 규칙 (작성자 공통)

형식은 정보의 모양이 정한다. 기본은 문장이고, 도식은 문장으로 읽는 것보다 그림으로 보는 게 빠를 때만 쓴다. 필요한 곳에서 빠뜨리는 것과 필요 없는 곳에 넣는 것은 같은 크기의 실수다.

작성자는 그리지 않는다. 수치와 사건을 구조화해서 내고(numbers, events), 그릴지는 코드가 아래 조건으로 정한다. 도식 종류는 네 가지뿐이다.

**배치: 포인트에 붙인다.** 페이지 순서를 정하는 것은 포인트 순서(중요도)다. 도식은 자기가 뒷받침하는 포인트 번호(`anchor`)를 갖고, 화면은 그 포인트 바로 아래에 그린다. 그래서 도식이 내용 흐름 안에 들어가고, 여러 포인트에 각각 붙을 수 있다. 도식마다 `context` 1~2문장(무엇을 어떤 조건에서 비교했는지)을 함께 낸다. 상한: 한 포인트에 도식 하나, 페이지당 B 최대 2개, D 최대 1개. 조건이 안 맞아 코드가 그림을 빼도 포인트 문장만으로 읽혀야 한다.

| 도식 | 작성자가 낼 것 | 코드가 그리는 조건 |
|---|---|---|
| A 소스 연결도 | 없음(코드가 근거로 만듦) | 항상 |
| B 수치 막대 | numbers 그룹 | 단위 하나, 값 3개 이상 / 또는 값 2개 + baseline + summary에 그 값이나 라벨이 나옴 |
| C 영상 타임라인 | 영상 근거 id(`vd:…@초`)를 point·number의 ref로 | 인용된 영상 시각이 1개 이상. 영상 근거를 처음 인용한 포인트 아래에 코드가 붙임 |
| D 사건 흐름 | events | 날짜 다른 사건 3개 이상 / 또는 2개 + flow_is_point |

- 원그래프, 다축, 색·크기·위치에 모두 의미를 싣는 도식은 없다
- numbers 그룹의 title에는 발견을 쓴다("모델별 성능" 대신 "Jeeves가 정확도 7%p 높음")
- 한 그룹은 한 단위. 단위가 다르면 그룹을 나누거나 문장으로
- 강조할 값 하나에만 emphasis, 전후 비교의 이전 값에 baseline
- A 소스 연결도는 개요 아래 고정 자리
