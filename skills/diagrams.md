# 시각 요소 규칙 (작성자 공통, S6-1)

형식은 정보의 모양이 정한다. 기본은 문장이고, 시각 요소는 문장으로 읽는 것보다 그림으로 보는 게 빠를 때만 쓴다. 필요한 곳에서 빠뜨리는 것과 필요 없는 곳에 넣는 것은 같은 크기의 실수다.

배치: 절 안에 둔다(그 절의 `visual`). 절마다 하나까지. 구조 상한(그룹 당 항목 수, 페이지 전체 개수)은 코드가 검사한다. 조건이 안 맞아 코드가 빼도 단락 문장만으로 읽혀야 한다.

| 시각 요소 | 쓸 때 | 작성자가 낼 것 |
|---|---|---|
| 타일(`head_tiles`, `tiles`) | 독립된 핵심 수치(결과·성능·가격·규모). 발표 시간·버전·날짜·개수 세기는 타일로 쓰지 않는다 | value(근거 표기 그대로)·label·note·refs |
| 막대(`bars`) | 같은 단위 값 2개 이상을 비교하고 그 비교가 그 절의 요지일 때(값 2개면 비교 대상이 분명할 때만) | title(발견을 말하는 제목)·context·unit·items |
| 표(`table`) | 행과 열이 있는 정보(여러 지표 × 여러 모델, 구간별 가격 등) | columns·rows(첫 열은 행 머리)·refs |
| 사건 흐름(`events`, 기존) | 날짜 다른 사건 여러 개, 또는 흐름 자체가 쟁점 | title·context·items |
| 슬라이드(`slide`) | 영상 토픽에서 코드가 고른 후보(`slide_candidates`) 중 그래프·표·수치가 몰린 것만. 글머리표 문장 슬라이드는 후보에 없다 | slide_candidates 중 id 하나, slide_caption |

- 원그래프, 다축, 색·크기·위치에 모두 의미를 싣는 도식은 없다
- 막대·표의 제목에는 근거 값 그대로의 발견을 쓴다("모델별 성능" 대신 "Jeeves 정확도 93.5%로 4개 중 최고"). 근거 값끼리 뺀 차이(%p)·배수를 새로 만들지 않는다
- 막대 한 그룹은 한 단위(unit을 비우지 않음, 정확도·시간·개수가 섞이지 않게)
- 강조할 값 하나에만 emphasis, 전후 비교의 이전 값에 baseline
- head_tiles에 쓴 수치를 절의 시각 요소에서 다시 쓰지 않는다
- 페이지 시각 요소는 `limits.visuals_target` 범위가 목표다(원문에 비교·구간·사건 재료가 있을 때만). 재료 없는 절에 억지로 만들지 않는다
